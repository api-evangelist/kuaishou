# Kuaishou

> Kuaishou Technology (快手) is a Beijing-based short-video and live-streaming platform, operating Kuaishou in mainland China and Kwai internationally. Its public developer surface is split between the Kuaishou Open Platform (open.kuaishou.com), a JSON Open API for third-party apps, mini programs and merchant tools secured with OAuth 2.0, and Kwai for Business (developers.kwai.com), the international advertising and marketing API.

Generated by the API Evangelist enrichment pipeline on 2026-07-19 (method: generated, source: apis.yml + repo artifacts). Not published by Kuaishou.

Important: both developer portals are JavaScript single-page applications with largely Chinese-language documentation gated behind developer registration. Kuaishou publishes no OpenAPI description, no /.well-known/ discovery document, no llms.txt and no MCP server. Everything below was verified by live HTTP probe.

## APIs

- [Kuaishou Open Platform API](https://open.kuaishou.com/): JSON HTTP API for third-party applications, mini programs and merchant integrations. Base URL https://open.kuaishou.com/openapi
- [Kwai for Business Marketing API](https://developers.kwai.com/): international advertising, creative and reporting API for the Kwai app. Base URL https://developers.kwai.com/rest/n/mapi

## Authentication

- OAuth 2.0 authorization code flow on the Open Platform
- Authorize: https://open.kuaishou.com/oauth2/authorize
- Token: https://open.kuaishou.com/oauth2/access_token
- The token endpoint returns the RFC 6749 `invalid_request` identifier inside Kuaishou's own result/error_msg envelope
- No OpenID Connect discovery document and no published scope reference; scopes require an approved developer account

## Conventions

- Style: RPC over HTTP, one path per operation, JSON request and response
- Error envelope (Open Platform): `{"result": <int>, "error_msg": "<string>", "request_id": "<string>"}`
- Error envelope (Kwai for Business): `{"timestamp", "status", "error", "message", "path"}`
- Application-level failures are returned with HTTP 200 and a non-zero `result` — inspect the body, not just the status
- Every Open Platform response carries a `request_id` for support correlation; Kwai edges also emit an `x-kslogid` response header
- Not RFC 9457 Problem Details; no idempotency key header verified; no rate-limit headers observed on unauthenticated probes

## Known error codes

- `100200100` — invalid or missing request parameters (参数为空 / 请求参数错误)
- `1026` — unknown Open API route, returned as `[1026] 404 NOT FOUND`
